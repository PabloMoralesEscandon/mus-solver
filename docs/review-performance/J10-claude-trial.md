# J10 terminal-action integration experiment: review (Claude)

Verdict: **APPROVE the limited conclusion**, with the caveats below. The trial is outside
production and was reviewed read-only:
- /tmp/mus-review-j10-terminal-trial.c, generated by -setup.py;
- the runner /tmp/mus-review-j10-terminal-trial.py;
- the log;
- the JSON, which embeds the source and the binary's SHA-256 (7549eff6…).

## Estimator correctness
- **Generated from production.** `-setup.py` builds the trial by copying production
  `mus_score_evaluate_with_options` out of src/mus_score.c and patching it. The "sample"
  mode calls the linked production evaluator, so the modes differ only in the integration
  block (trial.c:91-113, 127-128).
- **Integration rule.** At a JUEGO or PUNTO player decision with at most 2 legal actions, it
  applies each action and requires the child to be terminal. It takes that child's
  mano-perspective utility, undoes the action (with undo errors propagated), and, if every
  child is terminal, uses `Σ pᵢ · u(childᵢ)` as the hand's sample. `pᵢ` is the same
  average-strategy (or uniform for a missing node) distribution the normal path would sample
  from. If any child is not terminal, the state has already been restored and the decision
  is sampled normally.
- **Unbiasedness.** This is the conditional expectation of the sampled utility given the
  history (Rao–Blackwell): the mean stays unbiased and the per-hand variance cannot increase.
  - The data agree. Mode means differ by 0.00056 (35:35) and 0.00019 (39:39), against a
    per-mode standard error of about sqrt(0.84/320000) ≈ 0.0016–0.0018.
  - Variance never increases: −8.46 % and −0.06 %.
- **Different trajectories.** An integrated decision skips its random draw, so later
  seeded trajectories differ. The trial correctly claims no byte identity.

## Instrumentation
- **Setup:** one frozen policy (a 35:35 region table, 1,000 iterations per cell, seed 7).
  Both modes use the same seeds 0..31, with 10,000 hands per seed (320,000 hands per run).
- **Order and timing:** three alternating pairs on CPU0, timed with CLOCK_MONOTONIC around
  the evaluations only, with checkpoint loading excluded.
- **`integrated_hands`:** a process-global counter across all 32 seeds. It is 0 in sample
  mode, 67,515 (21 %) at 35:35 and 421 (0.13 %) at 39:39.
- **Statistics are deterministic:** the means and variances repeat exactly across repeats.

## What the numbers support
- **Per-hand sample variance** (`mean_sample_variance`, from 320,000 hands, relative error
  about 0.3 %):
  - 35:35: **−8.46 %**, clearly resolved;
  - 39:39: −0.063 %, which is **no measurable change**, consistent with only 0.13 % of hands
    integrated.
- **Time: not resolved at this scale.** Every run lasts only 0.22–0.39 s, and the ranges
  overlap:

  | Cell | Sampling (s) | Integration (s) | Median change |
  |---|---|---|---|
  | 35:35 | 0.364–0.386 | 0.374–0.385 | +2.87 % |
  | 39:39 | 0.225–0.232 | 0.225–0.232 | +1.74 % |

  Both medians fall within the run-to-run spread. Report them as "no resolved time change
  (within about ±3 % noise)", not as measured costs. The protocol's own rule says to lengthen
  short runs before judging relative differences.
- **Variance × time:** the arithmetic is correct (0.9154 × 1.0287 → −5.83 %;
  0.99937 × 1.0174 → +1.67 %). At 35:35 the result is driven by the resolved variance
  reduction, so an efficiency gain of about 5–8 % is fair. At 39:39 the +1.67 % is timing
  noise, and the honest reading is "no benefit".
- **Between-seed variance of the 32 means** (`seed_mean_variance`: −18.5 %, +6.2 %) has only
  31 degrees of freedom, a relative error of about 25 %. It is not informative and should not
  be cited as evidence.

## Conclusion
The coordinator's decision is well supported:
- keep ordinary sampling and the adaptive-budget option;
- document this as a bounded experiment;
- do not add a general integration mode on the basis of one frozen table and two cells.

The effect depends on the policy (21 % of hands integrated at 35:35 versus 0.13 % at 39:39),
the variance gain is modest where it exists, and the time cost is unresolved.

## Suggestions for the documentation (non-blocking)
1. State time as unresolved (±3 %), and describe the 39:39 result as "no measurable
   change", rather than printing the +2.87 % and +1.74 % as costs.
2. Cite the per-hand sample variance, and say that the between-seed variance was too noisy
   to use.
3. If this is ever revisited: lengthen the runs (for example 100,000 hands per seed or more
   repeats), test several tables and policies, and consider integrating the final
   showdown's chance nodes or decisions with more actions. The trial's rule is deliberately
   narrow.
